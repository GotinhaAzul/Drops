# Internal contracts

Names remain buddy-* per product.md; user-facing name Drops. Shared checkout: edit only assigned crate. Root handles proto, daemon, CLI and UI. No commits. Cargo workspace dependencies already declared. Rust installed by parent via mise; use `mise exec -- cargo ...`.

## buddy-ai (provider)
Public `ProviderConfig` serde Deserialize/Serialize/Clone/Debug with fields base_url:String, model:String, api_key_env:String, vision:bool, tools:bool, max_tokens_param:String (defaults). `Message`, `ToolDefinition`, `ToolCall` are serde_json::Value aliases (OpenAI wire objects). `ProviderEvent` enum: Text(String), Thinking(String), ToolCall(Value), Usage(Value). `pub async fn complete(config:&ProviderConfig, messages:&[Value], tools:&[Value], events:tokio::sync::mpsc::UnboundedSender<ProviderEvent>, cancel:tokio_util::sync::CancellationToken) -> anyhow::Result<Value>` returns full assistant wire message (role, content, tool_calls). Stream to events, accumulate. Public pure parser/request helpers at implementer's choice. API key read only from configured env var.

## buddy-agent (engine)
`AgentConfig` Clone: provider:buddy_ai::ProviderConfig, session_dir:PathBuf, project_dir:PathBuf, instructions:String, max_turns:usize, sudo:bool, external_tools:Vec<ExternalTool>, context_tools:Vec<ContextTool>. `sudo` is the daemon's persisted user opt-in to skip approval prompts; previews, validation, workspace confinement and `allow_shell` still apply. `ContextTool` carries name, description, JSON Schema parameters, risk and an async handler. The daemon uses it for anchor-scoped tools such as `window_content`; context tools never shadow built-ins, unknown risk is dangerous, and a handler error becomes a tool error result. Define ExternalTool serde struct (name,description,command:Vec<String>,parameters:Value,risk:String). `pub async fn run(config:AgentConfig, session_id:String, prompt:String, context:Value, allow_shell:bool, events:mpsc::UnboundedSender<Value>, approvals:mpsc::UnboundedReceiver<bool>, cancel:CancellationToken)->anyhow::Result<()>`. Events JSON with type text/thinking/tool_start/tool_result/approval/error/done and fields text, name, arguments as appropriate. approval shows exact tool name + arguments; approval bool consumed once per tool; denial, a closed channel and cancellation never bypass. AgentConfig.sudo skips only the prompt, chosen explicitly by the user. run loads JSONL history, appends context/user/assistant/tool events, executes until no tools or max turns. Read/write/edit root-scoped with canonical path validation; bash always dangerous and only with allow_shell; it needs approval unless sudo is set. Unknown/malformed tool calls produce model error results. Cancellation kills running child. `pub fn session_path(dir:&Path,id:&str)->Result<PathBuf>` validate id against traversal. Engine should emit done at end (daemon also resets state). Root will integrate API if needed.

## buddy-anchor (desktop)
Public serde Clone Debug `Anchor` enum tagged kind snake_case: Window{address:String}, Workspace{id:i64}. Public serde Clone Debug `Placement` {anchor:Anchor,x:i32,y:i32,visible:bool,label:String}. `pub async fn hit_test(x:i32,y:i32)->Result<Placement>`, `pub async fn refresh(anchor:&Anchor)->Result<Placement>`, `pub async fn context(anchor:&Anchor)->Result<Value>`, `pub async fn cursor_position()->Result<(i32,i32)>`. `pub async fn subscribe(events:mpsc::UnboundedSender<()> , cancel:CancellationToken)->Result<()>` subscribes socket2; signals changes (daemon re-queries). No mutation of desktop config. fallback window closed returns workspace placement. Context proc cwd/cmdline includes the anchor PID; working_context inspects a bounded descendant process tree for terminals and a uniquely matched default-server tmux pane. Editor launch arguments can identify a workspace. Ambiguous/shared-PID contexts do not select an automatic tool root. The daemon exposes tool_workspace and gives configured project_dir priority over detected workspace roots. hit test top floating window first, excludes Drops/quickshell surfaces, respects monitor and visible workspace. Tests pure hit testing.

Placed blobs persist a decoration `offset: [x,y]` relative to the anchor reference point. `Placement` remains a resolved rendering position; anchor identity stays a window address/workspace ID. The daemon applies the offset after hit testing and on every refresh.

Geometry tracking uses direct read-only control-socket queries for window anchors because socket2 does not report all floating position changes. Full context capture remains on-demand. Metadata saves serialize outside the application mutex, with movement saves coalesced at 500 ms.

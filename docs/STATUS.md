# Implementation and validation status

This is the initial Drops build. The feature inventory below separates code from checks that require an actual desktop or model endpoint.

## Implemented

- Six Rust workspace crates following the spec's boundaries.
- OpenAI-compatible Chat Completions, SSE text/reasoning/usage and fragmented indexed tool calls, omitted tool IDs and non-streaming fallback.
- Agent continuation, malformed-call recovery, project-scoped file read/write/edit, gated shell and external stdio tools, markdown instructions/skills, JSONL sessions.
- Read-only workspace overview with source-labelled previews; Git-ignore-aware, glob-filtered and paginated file search with ASCII case-insensitive matching and match-centered excerpts. Basic argument validation precedes approvals, structured discovery outputs preserve JSON, and regular-file reads enforce byte caps during I/O.
- A bounded per-turn `brief` summarizes the current anchor/window, workspace, local document and capture evidence with freshness, ambiguity, missing-context and verification-hint cues. It reads no extra files. Older context snapshots remain in the JSONL export but are omitted from model history while a fresh bundle exists.
- Session-scoped `task_memory` stores a bounded goal, decisions, pending work and verified results in the session JSONL. Verified entries require evidence, paths are confined to the current tool workspace, workspace changes remove path-scoped items, anchor changes remove anchor-scoped items, and clear/remove/fork/export/restart follow the session lifecycle.
- `write`, `edit` and `append` approvals include a concrete unified diff. Calls that cannot apply are reported before approval; files changed since a read (including during approval waiting) are refused; writes are atomic, preserve existing modes, and copy overwritten content to `.drops/backups` with a bounded per-file history. Denial mutates nothing.
- NDJSON Unix socket daemon, private socket, CLI/Waybar state, persistent blob metadata, up to three independent sessions, clear/export/fork, per-tool approvals and cancellation.
- Hyprland queries, hit testing, window/workspace anchors, reconnecting socket2 updates, persisted decoration offsets and context with window geometry and process metadata.
- Window content capture sends a bounded preview; a read-only `window_content` tool can search or page through a larger accessibility/terminal capture on demand, cached per turn.
- Automatic folder detection is the default. Live explorer locations, additional terminal/editor classes, local URIs and JSON editor workspace files extend discovery; per-Drop folder choices stay inside configured boundaries. Idle placement/context refreshes are fenced against newer turns and anchor changes.
- Structured app context adds document/page URIs, actual highlighted-text ranges and explorer-selected items. File paths are verified against the detected folder and tool boundary, URLs omit credentials/query/fragment, and browser titles never select local roots. Idle metadata-only refreshes avoid whole-document reads; normal sends refresh the full context. The chat offers selection/explorer quick actions and a readable context inspector, with raw JSON behind a details switch.
- Native Omarchy top-bar widget with a redesigned panel: live status and inline failure text in the header, numbered drop pills, a selected-Drop hero card with the chat action, file-access and in-window evidence cards, a six-face appearance row with a selection ring, compact Lively/Sudo switches, and create/delete controls in the footer. Settings uses a segmented provider control and a pinned save footer; the context inspector uses readable cards and a pinned close header. Smooth pointer-following drag animations remain.
- QML panel plus an in-place chat bubble: contextual greetings, quick actions, an inline composer, approvals and a scrollable conversation. Sending collapses the bubble into a truncated reply preview above the drop, and the drop avatar stays visible during window capture. Stable surface identity during streaming, exact approval cards, context inspection via the anchor label, and a stop control.
- Thinking-model reasoning is shown as one collapsed, expandable block with a bounded scroll area; `[appearance].thinking_mode` hides it or expands it by default.
- TOML provider selection, anchor rules and external executable declarations; local install script, one-click launcher and example Waybar configuration. Model settings offer a custom OpenAI-compatible endpoint or Opencode Go, which fetches the gateway model list and stores its key privately.

## Validation limits

Real Ollama/llama-server/hosted SSE recordings are not claimed: provider fixtures are synthetic compatibility fixtures. Two live endpoint implementations must still be checked to close milestone 1 exactly as written. Opencode Go was validated against its public model-list endpoint and request routing, but a complete live chat turn requires an Opencode Go subscription key and was not run here.

The video session was restored during implementation. The actual `ui/shell.qml` then loaded successfully on Hyprland with the Wayland backend (`Configuration Loaded`, no runtime QML errors). Offscreen checks also load the controls using a substitute window surface. A disposable Foot terminal also passed live hit-testing, socket2 workspace hide/return and window-automatic deletion when an attached window closes, with the UI connected. Actual pointer dragging, multi-monitor mapping and fractional scaling still require interactive validation.

The context brief and task memory are verified headlessly and with the fake/real anchor fixtures already used for workspace detection; no additional live compositor pass was performed for this increment beyond the existing checks. Stale-read receipts are per-run only, so a file changed between separate turns is caught only when `expected_content` is supplied. Atomic replacement protects partial writes on one filesystem; hostile local filesystem races between canonicalization and rename are outside the guarantee. Backup pruning keeps the ten newest copies per target, and backup files are ordinary workspace files that a later approved action or the user can modify.

Window content capture now uses matched-window accessibility, optional matching tmux scrollback, visible-window OCR and vision attachments. Live disposable terminal, GTK editor and Chromium page checks passed through a local mock endpoint. Complete terminal scrollback and full page/document text depend on accessibility or tmux support; OCR covers only the visible crop. Locked sessions refuse capture. Colors, size and roundness are configured in `[appearance]`; automatic Omarchy theme tracking remains follow-up work. Per-tool permission overrides and richer anchor-scoped tool lists also remain follow-up work; the policy is deliberately fixed: core file mutations and shell commands require approval, with one global opt-in sudo mode that skips only the prompt. Sudo mode still runs previews, validation and workspace confinement, and never grants shell where `allow_shell` is false.

A five-second debug-build sample with one real window drop measured 0.20% of one CPU core and 13.4 MiB daemon RSS. This excludes Quickshell memory and is not a full performance benchmark. Window geometry is checked every 200 ms through the control socket only while window drops exist; workspace-only sessions do no geometry IPC. The five-minute onboarding and ten-minute external-tool onboarding targets have not been measured.
